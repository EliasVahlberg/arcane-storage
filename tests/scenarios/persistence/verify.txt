# Persistence, phase 2 of 2: assert the state written before the restart survived.
#
# Run against the world left by tests/scenarios/persistence/write.txt, in a second boot:
#
#   tools/run_scenario.sh --keep tests/scenarios/persistence/verify.txt
#
# 'make persistence' and 'make scenarios' both do this for you.
#
# Deliberately contains no 'reset' and no 'clear'. Either would destroy the very state being
# verified, so this file must only ever read.
#
# Every number here is copied from write.txt. If the write phase did not run, these fail as
# zeros rather than passing quietly.

# Case 1: a plain chain, with its contents.
harness expect units 0 0 2
harness expect item 0 0 ironbar 50

# Case 2: the conduits came back, so the terminal still reaches the unit behind them.
harness expect units 0 6 1
harness expect item 0 6 stone 20

# Case 3: still four units and still 10 bars -- not 20, which is what a lost visited set
# would report by registering the multi-path unit twice.
harness expect units 0 10 4
harness expect item 0 10 ironbar 10

# Case 4: a region the spawn area never touches.
harness expect units -40 -40 1
harness expect item -40 -40 stone 5

# Nothing appeared or vanished anywhere on the level.
harness expect total ironbar 60
harness expect total stone 25
