# Conduits: reach without capacity.
#
# The unit tests cover the traversal in isolation. This covers the part they cannot: that the
# game recognises a real placed conduit, which works by object ID rather than by an object
# entity, since a conduit has no state.

# Scenarios share one server boot, so start from no storage objects anywhere on the
# level -- clear only covers a radius, and expect total scans everything.
arcanestorage reset

arcanestorage clear 20

# --- A run of conduits joins units the terminal could never reach alone (0,0) ---
arcanestorage place terminal 0 0
arcanestorage place conduit 1 0
arcanestorage place conduit 2 0
arcanestorage place conduit 3 0
arcanestorage place unit 4 0
arcanestorage place unit 5 0
arcanestorage fill 4 0 ironbar 30
arcanestorage fill 5 0 ironbar 30

# Two units, not five objects: a conduit must never contribute capacity.
arcanestorage expect units 0 0 2
arcanestorage expect total ironbar 60

# --- A conduit conducts, it does not bridge (0,6) ---
# One empty tile at 2,6 still severs the network, exactly as it does between units.
arcanestorage place terminal 0 6
arcanestorage place conduit 1 6
arcanestorage place conduit 3 6
arcanestorage place unit 4 6
arcanestorage expect units 0 6 0

# --- A conduit branches, which is the reason it exists (0,10) ---
# Routing around a base means one conduit feeding units in different directions.
arcanestorage place terminal 1 10
arcanestorage place conduit 1 11
arcanestorage place unit 0 11
arcanestorage place unit 2 11
arcanestorage expect units 1 10 2

# --- Breaking a conduit orphans everything beyond it (0,14) ---
# The same degradation as breaking a unit mid-chain, and the reason isValid checks the
# network every tick rather than trusting what it found when the terminal was opened.
arcanestorage place terminal 0 14
arcanestorage place conduit 1 14
arcanestorage place unit 2 14
arcanestorage expect units 0 14 1
arcanestorage break 1 14
arcanestorage expect units 0 14 0
