# Measures the cost the interface pays every time it redraws, against the largest network the
# mod allows: MAX_UNITS is 64, so this is the ceiling rather than a sample.
#
# Every slot holds a different item, because distinct items are what aggregation scales on —
# 2560 slots holding one item type would be cheap regardless of size and would prove nothing.
#
# This scenario exists because "usable with a large network" was an open claim supported by
# reasoning rather than numbers. Two costs had been removed by reading the code, and reading
# the code cannot tell you whether what remains fits in a frame.

harness reset
harness place terminal 0 0

# 64 units, 200 timed aggregations after a warm-up. Fails if one aggregation exceeds 2ms, on
# the grounds that a frame has 16.67ms for everything and the item list is one part of one
# panel. Beyond that line the fix is caching invalidated by inventory changes, not tuning.
harness bench 0 0 64 200

# The same network read through the assertions the other scenarios use, so a regression in
# aggregation shows up as a wrong number here and not only as a slow one.
harness expect units 0 0 64
harness expect capacity 0 0 2560 2560
